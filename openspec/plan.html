OpenSpec Plan: Template Disk Sizing Fix

Change: template-disk-sizing | Repo: github.com/mkdev-ai/devsy-proxmox-provider | Branch: feature/template-disk-sizing

Problem

The template base disk the workspace is built from is too small. scripts/setup.sh creates the cloud-init template from the Ubuntu cloud image with no size argument, so the template lands at the image default — 3584 M (~3.5 GB), as the Proxmox web UI screenshot of devsy-ubuntu-24-04 (ID 9000) confirms (virtio0 = 3584 M). The provider's VM_DISK_SIZE option only resizes the clone after cloning, and did so against a hard-coded "expect ~17 GB template" assumption, so it could never produce the requested capacity. The result: fatal: write error: No space left on device mid git clone / docker pull after VM start.

Root cause (verified)

  • The template base disk is the Ubuntu cloud-image default (~3.5 GB), not the requested 50 GB.
  • VM_DISK_SIZE applies to the clone, only after cloning, and used a brittle +33G calc from a guessed 17 GB template base.
  • The clone's repo fetch then fails on the small disk before the requested 50 GB is ever available.
  • The agent's local data root is a separate filesystem (DEVSY_HOME) and is unrelated to the Proxmox template.

Design decisions

  • 1. Size the template at creation time: pass --size to qm importdisk (setup.sh --template-disk-size, MiB, default 3584).
  • 2. Resize the clone to exactly VM_DISK_SIZE, computed from the real template base, executed BEFORE the VM starts.
  • 3. Remove the hard-coded templateDiskGB := 17 assumption.
  • 4. Document the root-run template rebuild step (qm importdisk --size is additive per host, so template rebuild required).
